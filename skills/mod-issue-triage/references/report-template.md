# Mod 问题报告模板

本文件是 `mod-issue-triage` Skill 的配套参考，用于生成标准问题报告。
字段固定为 7 个：问题标题、问题现象、运行环境、复现步骤、还需要的信息、当前判断、免责声明。

## 一、空模板

```markdown
# {问题标题}

## 问题现象
{用户观察到的现象、出现时机、关键报错原文；区分用户确认与推测}

## 运行环境
- 游戏版本：{... 或 "未提供"}
- Mod 版本：{... 或 "未提供"}
- 加载器：{... 或 "未提供"}
- 操作系统：{... 或 "未提供"}
- 其他 Mod：{... 或 "未提供"}

## 复现步骤
1. {用户提供的第一步}
2. {用户提供的第二步}
{缺失步骤写"未提供"；不要脑补操作}

## 还需要的信息
- {缺失信息项}：{为什么需要它}
- {缺失信息项}：{为什么需要它}

## 当前判断
{一句话推测，或以"信息不足，无法判断"结尾；推测须标注"推测"}

## 免责声明
本报告仅整理用户提供的信息，未修复 Bug、未运行游戏、未分析根因，不构成修复承诺。
```

## 二、示例（Minecraft Fabric）

> ⚠️ 此为示意，实际输出以用户提供的信息为准。

```markdown
# 破坏自定义木门后客户端崩溃

## 问题现象
玩家在单人存档中破坏一个自定义木门方块时，客户端立即崩溃至桌面，崩溃前没有可见提示。（用户确认）

## 运行环境
- 游戏版本：1.20.1（用户确认）
- Mod 版本：1.7.0（用户确认）
- 加载器：Fabric Loader 0.15.11（推测，来自日志文件名）
- 操作系统：Windows 11（用户确认）
- 其他 Mod：未提供

## 复现步骤
1. 进入一个单人存档。
2. 在创造模式下放置自定义木门。
3. 用任意工具破坏该木门。
4. 客户端崩溃。

## 还需要的信息
- Fabric API 版本及完整 Mod 列表：用于排查依赖冲突。
- 完整崩溃日志（crash-report 文件）：目前只有片段，不足以定位。
- 全新世界中是否同样出现：用于判断是否与存档数据相关。

## 当前判断
推测：崩溃发生在方块被破坏后的客户端回调阶段，可能与自定义方块实体清理有关；信息不足，暂不能确认根因。

## 免责声明
本报告仅整理用户提供的信息，未修复 Bug、未运行游戏、未分析根因，不构成修复承诺。
```

## 三、填写要点

- 只用用户提供的信息；无法从输入中确认的内容一律标注"未提供""不确定"或"推测"。
- 用户前后的说法冲突时，写"矛盾：用户先说 A，后说 B"，不要替用户选择。
- 日志只引用原文片段，不补全、不改写关键报错。
- 本模板与示例不包含任何修复建议或根因结论。
